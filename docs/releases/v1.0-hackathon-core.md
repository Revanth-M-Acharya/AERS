## 1. System Overview

**SMART AEGIS** (Automated Emergency Grid & Intelligent Shield) is a production-grade, distributed cyber-physical emergency response platform engineered specifically for **QNX Neutrino RTOS** running on an edge cluster of **Raspberry Pi 4 Model B** single-board computers.

The system dynamically detects inbound emergency ambulances via optical IR proximity sensors and GPS telematics, calculates optimal city-wide priority paths using A* heuristic graph routing, resolves multi-vehicle corridor contention via medical triage scoring, and synchronizes roadside traffic signal controllers via QNX microkernel message passing and hardware relay banks to create safe, pre-cleared green corridors without disrupting municipal safety.

## 5. QNX SDP 8.0 Native Real-Time Features

### 5.1 QNX Resource Manager (`/dev/aegis/*`)
Exposes six standard POSIX character device nodes under `/dev/aegis/`:
* `/dev/aegis/coordinator`: Central coordinator status and preemption command portal.
* `/dev/aegis/intersectionA`, `/dev/aegis/intersectionB`, `/dev/aegis/intersectionC`: Roadside node telemetry.
* `/dev/aegis/cluster`: 4-SBC cluster health telemetry and composite scoring.
* `/dev/aegis/system`: QNX Neutrino RTOS system metrics, memory, and uptime.
* Supports standard `open()`, `read()`, `write()`, `close()`, and `devctl()` handlers.

### 5.2 Native Synchronous Message Passing (Rendezvous IPC)
* True QNX rendezvous semantics: `ChannelCreate(0)`, `ConnectAttach()`, `MsgSend()`, `MsgReceive()`, `MsgReply()`.
* Sender thread strictly blocks in `MsgSend()` until receiver thread executes `MsgReply()`.
* Typed schemas: `HEARTBEAT` (`0x1001`), `REGISTRATION` (`0x1002`), `CORRIDOR_REQUEST` (`0x1003`), `SIGNAL_COMMAND` (`0x1004`), `STATUS_UPDATE` (`0x1005`), `RECOVERY_MESSAGE` (`0x1006`).

### 5.3 Microkernel Pulses (`SIGEV_PULSE`)
* Non-blocking kernel event delivery via `MsgSendPulse()` and `MsgReceivePulse()`.
* Seven defined application codes:
  1. `PULSE_CODE_WATCHDOG = 1`
  2. `PULSE_CODE_HEARTBEAT = 2`
  3. `PULSE_CODE_CORRIDOR_TIMEOUT = 3`
  4. `PULSE_CODE_DEADLINE = 4`
  5. `PULSE_CODE_SHUTDOWN = 5`
  6. `PULSE_CODE_FAULT_RECOVERY = 6`
  7. `PULSE_CODE_INTERRUPT = 7`

### 5.4 High-Resolution Monotonic Timers
* Monotonic timers created via `timer_create(CLOCK_MONOTONIC)` bound to `SIGEV_PULSE`.
* Armed via `timer_settime()` for periodic intervals and one-shot timeouts with microsecond jitter tracking.

### 5.5 Real-Time Thread Scheduling Hierarchy
* Strict 5-tier `SCHED_FIFO` priority hierarchy:
  - **Priority 30 (Highest):** Coordinator Core Dispatch Thread
  - **Priority 25:** Intersection Controller Threads (Real-Time GPIO Actuation)
  - **Priority 21:** Dynamic Corridor Release & Timeline Engine
  - **Priority 12:** Health Monitor & Deadline Supervision
  - **Priority 5:** Telemetry, Event Logging & devctl Handlers
* `PrioInheritMutex` utilizing `PTHREAD_PRIO_INHERIT` to eliminate unbounded priority inversion.

### 5.6 Hardware Interrupt Attachment
* Attached via `InterruptAttachEvent()` binding GPIO transitions directly to kernel pulse delivery.
* Lines: GPIO 12 (Approach IR), GPIO 13 (Departure IR), GPIO 16 (Emergency Button), GPIO 24 (Relay Fault).

### 5.7 Industrial devctl() Commands (Class 'A' = 0x41)
* `DCMD_AEGIS_GET_SYSTEM_STATUS`
* `DCMD_AEGIS_GET_NODE_STATUS`
* `DCMD_AEGIS_START_CORRIDOR`
* `DCMD_AEGIS_STOP_CORRIDOR`
* `DCMD_AEGIS_RESET_NODE`
* `DCMD_AEGIS_READ_TELEMETRY`
* `DCMD_AEGIS_READ_LOGS`
* `DCMD_AEGIS_ENABLE_DIAGNOSTICS`
* `DCMD_AEGIS_RUN_SELF_TEST`

## 9. Known Limitations

1. **Simulated Hardware Fallback:** When compiled on macOS/Linux hosts without QNX headers, the system gracefully engages high-fidelity POSIX simulation for CI testing. Physical register operations require deployment to the QNX Raspberry Pi 4 image.
2. **Satellite GPS Hardware:** Vehicle telematics use high-precision internal route kinematics; connecting physical NMEA-0183 UART serial GPS receivers represents a field hardware upgrade.
3. **In-Memory Registry Persistence:** Node and ambulance registries synchronize dynamically across network reconnects; survival across total simultaneous cluster power cuts requires external NVRAM storage.
